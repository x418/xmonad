# Names the X11 build exports and the river build does not, with what it would
# take to change that.
#
# The rule for the river backend is that anything which cannot be faithfully
# ported is not exported.  A name that is present but inert is worse than one
# that is absent: absent fails at the call site, at compile time, naming the
# file and line, and whoever reads that error learns something true.  A no-op
# that typechecks teaches them nothing until the behaviour is missing at
# runtime, by which point the backend is the last place they will look.
#
# tests/api/check-subset.sh requires this list to match the build exactly: a
# name dropped without an entry fails, and so does a stale entry for a name
# river has since grown.  Only the first word of each entry is read.
#
# Sections are ordered by how fixable they are, most first.  Confidence varies
# and is stated: nothing here has been tried against a live river.


################################################################################
# 1. Implementable, but the timing semantics differ and that needs deciding
#
# river permits window management state to change only during a manage
# sequence, and applies rendering state only at render_finish.  Upstream these
# are all "do it now" operations, and callers rely on that.  They could be
# exported as operations queued for the next sequence, but a contrib module
# that assumes immediacy would then see surprising ordering rather than a
# compile error -- which is the tradeoff the whole backend is built to avoid.
#
# Held back deliberately.  Worth revisiting once something real has run against
# river and the ordering hazards are concrete rather than theoretical.

manage                  FIX: adopt into the WindowSet, deferred to the next manage_start.  See WM.adoptNewWindows.
tileWindow              FIX: record the placement; propose_dimensions at manage, set_position at render.
setTopFocus             FIX: river_seat_v1.focus_window, deferred to the end of the manage sequence.
setFocusX               FIX: as setTopFocus, plus clear_focus when the target is gone.
setInitialProperties    FIX: set_borders + set_tiled + set_capabilities at adopt time.


################################################################################
# 2. State across a restart -- fixed; nothing is dropped for it any more
#
# This section used to list StateFile, writeStateToFile, readStateFile and
# stateFileName, on the grounds that river object ids are per-connection and
# recycled after wl_display.delete_id, so an id written by one window manager
# is meaningless to its successor.  That much is still true; the conclusion
# was wrong.
#
# river_window_v1.identifier is generated from the window's
# ext_foreign_toplevel_handle_v1, which belongs to the window and not to the
# window manager's connection -- river creates one only if the window has none
# already, with a comment saying so is for the restarting-window-manager case.
# And the open question here, whether identifier is delivered for every window
# before the first manage_start, is answered yes by construction:
# WindowManager.manageStart() iterates every window, sending window and
# identifier, and only then sends manage_start.
#
# So the state file is keyed on identifier and resolved during the first manage
# sequence.  See XMonad.Operations.StateFile and XMonad.River.WM.restoreState.


################################################################################
# 3. A degenerate answer would be truthful, but the answer would mislead
#
# `pure ()` is vacuously correct for both of these -- river grabs nothing, so
# there is nothing to release and nothing to configure.  They are held back
# anyway, because unlike cleanMask, extraModifiers, isRoot, clearEvents and
# cacheNumlockMask (all now exported, for exactly the reason this section
# rejects these two) their contract is advice rather than state.
#
# clearEvents is here for a different reason: `pure ()` is right, but its
# EventMask argument cannot be kept.  That type is a bitmask over the X
# protocol's event taxonomy, and river exports none of the constants that fill
# it, so the parameter would be a slot nothing can fill.  Changing the shape of
# a signature to make a name fit is the sort of accommodation this backend
# avoids.
#
# unGrab's documentation tells the caller to run it before spawning a screen
# locker, so the locker can take the keyboard without a sleep first.  A caller
# writes `unGrab >> spawn "slock"` and believes the keyboard has been handed
# over.  Under river it has not: a locker acquires input through
# ext-session-lock-v1, which has nothing to do with this call.  Succeeding
# silently would be true about grabs and false about the thing being asked.
#
# setButtonGrab is milder and the same shape: its Bool says whether to
# intercept clicks, and river settled that when the pointer binding object was
# created.  Taking the argument and discarding it misrepresents who decides.

clearEvents             HELD: correct as `pure ()`, but its EventMask parameter cannot be kept.
unGrab                  HELD: `pure ()` is true about grabs and misleading about handing over the keyboard.
setButtonGrab           HELD: `pure ()` would accept a Bool that river already decided.


################################################################################
# 4. No fix -- Wayland has no such concept
#
# Where a name's *purpose* survives under a different spelling, that is noted.
#
# withDisplay is *not* here.  `type Display = Connection` -- an X11 Display is
# the handle to the X server and this is the handle to the Wayland one, which
# the protocol itself calls wl_display -- so the name and the signature both
# survive.  What does not survive is anything that called an Xlib function on
# it, and those names are absent, so such code fails at the call that is
# genuinely unportable rather than at withDisplay.

getAtom                 NO FIX: Wayland has no atom namespace.  Nothing to intern, nothing to intern against.
atom_WM_STATE           NO FIX: as getAtom.  Purpose survives as river_window_v1.hide/show.
atom_WM_PROTOCOLS       NO FIX: as getAtom.  There is no protocol negotiation to advertise.
atom_WM_DELETE_WINDOW   NO FIX: as getAtom.  Purpose survives as river_window_v1.close (xdg_toplevel.close).
atom_WM_TAKE_FOCUS      NO FIX: as getAtom.  Purpose survives as river_seat_v1.focus_window.
stringProperty          NO FIX: no window properties at all.  Nearest: app_id, title, unreliable_pid, identifier.
getStringProperty       NO FIX: as stringProperty.
setWMState              NO FIX: WM_STATE is X11's.  Purpose survives as hide/show, which is how workspaces work.
initColor               NO FIX: no colormap to allocate against.  XMonad.River.parseColorMaybe answers the same question -- is this a usable colour -- without one, and is what setWindowBorderWithFallback (which is back, taking BorderColor where X11 took Pixel) falls back from.
mkGrabs                 NO FIX: returns KeyCodes, which need the keymap.  river_xkb_config_v1.create_keymap
                      # passes an fd, and this backend speaks the wire protocol directly precisely because
                      # nothing else in it needs SCM_RIGHTS.  Bindings are river objects instead; see WM.bindSeat.
sendReplace             NO FIX: river permits one window manager and answers a second with `unavailable`.
                      # There is no selection to steal.  Swapping is what --restart does, and river keeps
                      # every client alive across it.
xmessage                NO FIX: an X11 client.  Diagnostics go to stderr, and so to the journal.
